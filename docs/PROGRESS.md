## 2026-11-07 「自機が勝手に左へ移動する」問題の解決

- 根本原因: `ui.asm show_msg` の `ld b,l / ld c,h` が BC = (L<<8)|H となり
  コメント通りの「BC = 8r」にならない (HL のバイトスワップ = 5000h 相当になる)。
- 結果 "STAGE n" バナーの書き込み先が `D000h + (32r + 5000h + col)` = 12151h となり
  16bit ラップで **RAM コード領域 2151h-2155h** に飛び、そこは `read_keys` の
  ↑キー・デコード命令 (`srl a` ×5) の途中だったため ↑押下が W_KEYS bit2 (左) と誤認識。
- 修正: `ld b,h / ld c,l` に変更 (BC = 8r 正しく)。
- 調査にはエミュレータ CLI の拡張を使用 (詳細は docs/DEBUG_STATE.md §12):
  - `--dump-at FRAME@ADDR,LEN` (指定フレーム時点のメモリダンプ)
  - `--watch-write` の重複排除をアドレス別 (PC,value) に変更しログへ HL/BC/DE/SP を併記
  - `tmp/code_compare.py` で実行時 RAM コード領域と `out/sideb.bin` を diff
- 検証: frame 989 時点コード領域 diff 0。↑押下で W_KEYS=01h (上)・y 140→112 に移動・
  x 不変 (左移動なし)。"STAGE" バナーが画面行10中央に表示されるようになった。
- `input.asm` の TEMP DEBUG ストア (B0E9h/B0EAh/B0EBh) を削除。
  ストローブ後 `nop` ×4 (マトリクス安定待ち) は実機向けに残置。
- 既知の小問題: MSG_STGn の空白が 00h (終端コードと共用) のため
  バナーは「STAGE」までしか表示されない (数字未表示)。

## 2026-11 描画不具合の解消 (スクロール方向 & 残像・黒列)

- **スクロール方向を逆転**: `do_scroll_shift` を「行を上へ LDIR + 最下段に新行」から
  「行を**下へ LDDR** (重なりシフトのため後方コピー) + **最上段**に新行」に変更。
  地形が上端から入って下へ流れる = 前進 (魔城伝説型) の見た目になる。
  敵 (y=0 から降下)・自弾 (上昇) との方向整合も回帰テスト済み
  (1066f のミラー行1-21 == 1060f の行0-20 を機械検証)。
- **ERASE2X2 の D レジスタ寿命バグ解消** (自機右下に黒セルを毎フレーム焼き付ける):
  BR 値を D に保持したまま `ld de,39` を再ロードするため D=00h に壊れ、
  消去時に自機右下セルへ常に 00h (黒) を書いていた。シフトで下流に黒列として
  蓄積 (修正前のスクリーンショットの階段状黒塊の正体)。
  → BR 値は書き込み時にミラーから直接読み直す方式に変更。
- **ERASE1X1 の PCG 属性アドレスバグ解消** (1x1 オブジェクトの軌跡残像):
  属性を `セル+2000h` (F000h領域, 実質捨て) に書いており、旧セルの PCG 属性が
  4Ah (バンク1) のまま残って地形がバンク1パターンで描画されていた
  (炎状の残像連鎖・黒い軌跡の正体)。→ `+0800h` (DC00h 基準) に修正。
- 検証: 1060〜3600f の E2E で黒列・残像ゼロ、tick 正常増加、2400f 以降も state=FIELD を確認
- デバッグ支援ツール追加: `tools/ppm2png.py` (PPM→PNG 変換),
  `tools/dumpanalyze.py` (--dump 出力の VRAM/ミラー比較。PowerShell リダイレクトの
  UTF-16LE を自動判別), `tools/symlookup.py` (main.sym アドレス逆引き)
