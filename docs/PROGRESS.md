## 2026-11-10 サウンド修正: SE ストリーム暴走 (BGM ループ崩れの正体) / エンディング BGM

- **1面 BGM がループ点でおかしな音になる** → SE ドライバのバグが原因。
  `snd_tick_se` が `[dur][バイト数]` ヘッダの先頭 (dur) を「バイト数」として
  消費するため 1 エントリごとにポインタが 2B ズレ, SE 領域 (実 501Fh-5082h) を
  飛び出して pcg_restore データをバイト数解釈しながらデタラメ PSG 出力を続けて
  いた (E2E watch で V_SE_PTR: 503C→503F→5131→51CA→52CF を観測)。
  SE は BGM の直後に out されるため BGM がノイズでかき消され,
  「ループできずにおかしな音が鳴る」ように聞こえていた。
  BGM ループ機構自体は正常 (PC 2658h=BGM_REW でリワインド, 2 巡目進行を確認)。
- `snd_tick_se` を BGM と同一進行 (dur 待ち + バイト数分 out) に改修。
  V_SE_DUR (B0F0) を追加し V_SE_ACT を B0F1 へ, 拡張ワーク (W_SPAWNMAX..W_RFDP)
  を +1 オフセットシフト。SE が作曲意図どおりの dur で鳴るようにもなった。
- **エンディング BGM も壊れていた**: `ld de,BGM_END` は `dw BGM_CLEAR` の
  ポインタ値をストリームとして再生するためデタラメ。BGM_CLEAR を直接指定し,
  musicgen.py の BGM_END 出力を削除して sound_data.asm を再生成
  (曲ラベルは全て +22B シフト: BGM_FIELD1=$2765 等)。
- **検証**: 静的シミュレーションで全 5 曲が FFh 終端で 2 回リワインド,
  全 3 SE が 00h 終端で停止 (領域オーバーなし)。E2E (--watch-write B0EE/B0E8)
  で SE ポインタは 5033h→5038h→…→504Fh と SE_SHOT 6 エントリをちょうど
  消費して停止, 暴走ゼロ, BGM は PC 266Ah (BGM_REW) でリワインド。
  ビルド通過 (sideb.bin 34456B)。

## 2026-11-07 フィードバック対応: 色マージ完全化 / アイテム固定 / メッセージ黒帯廃止

- **色マージ完全化** (video.asm sprite_recolor_field): 置換を「行単位」から
  「ピクセル単位」へ変更。黒 (3 プレーン全 0) のピクセルを検出して各プレーンに
  フィールド色成分を OR で塗り、自機・敵・宝箱・アイテム・ボス・爆発の

  (bit 単位のまま AND すると black の bit0 = 右端 1 列しか置換されない)。
  SPRC_TBL ポインタは W_RFTBL (ワーク RAM) に退避 — OUT E5h 窓中でも
  B000 域は通常 RAM として読み書きできる。呼び出し側の HL は push/pop で保護。
- **アイテム固定化** (item.asm): 宝箱を撃ち抜いた位置にパワーアップが出現し
  移動しない。+5 を寿命タイマに転用し PWUP_LIFE = 240 (約 4 秒) で消滅。
- **メッセージ黒帯廃止** (ui.asm): 行全体の PCG 属性 OFF をやめ、テキストが
  入っているセルだけ PCG OFF (00h) に。さらに色属性 (0D800h+) の背景 bit0-2 を
  フィールド色にして文字が地形に浮く (前景 bit4-6 とフォントページ bit7 は
  現状維持)。空白セルは PCGATTR_BANK0 に戻すので地形はそのまま見える。

  1. msg_attr_off で VRAM ベースアドレスをそのまま add hl してテキストポインタが

  2. ピクセル単位 recolor で HL (SPRC_TBL ポインタ) を作業レジスタに使い契約違反 →
     テーブル走査が飛び地を読んでデータ領域ジャンプ。W_RFTBL 退避 + push/pop で解決
  3. 「black & c & 01h」では black マスクの bit0 (右端 1 列) しか置換されない →

## 2026-11-07 「自機が勝手に左へ移動する」問題の解決

- 根本原因: `ui.asm show_msg` の `ld b,l / ld c,h` が BC = (L<<8)|H となり
  コメント通りの「BC = 8r」にならない (HL のバイトスワップ = 5000h 相当になる)。
- 結果 "STAGE n" バナーの書き込み先が `D000h + (32r + 5000h + col)` = 12151h となり
  16bit ラップで **RAM コード領域 2151h-2155h** に飛び、そこは `read_keys` の
  ↑キー・デコード命令 (`srl a` ×5) の途中だったため ↑押下が W_KEYS bit2 (左) と誤認識。
- 修正: `ld b,h / ld c,l` に変更 (BC = 8r 正しく)。
- 調査にはエミュレータ CLI の拡張を使用 (詳細は docs/DEBUG_STATE.md §12):
  - `--dump-at FRAME@ADDR,LEN` (指定フレーム時点のメモリダンプ)
  - `--watch-write` の重複排除をアドレス別 (PC,value) に変更しログへ HL/BC/DE/SP を併記
  - `tools/code_compare.py` で実行時 RAM コード領域と `out/sideb.bin` を diff
- 検証: frame 989 時点コード領域 diff 0。↑押下で W_KEYS=01h (上)・y 140→112 に移動・
  x 不変 (左移動なし)。"STAGE" バナーが画面行10中央に表示されるようになった。
- `input.asm` の TEMP DEBUG ストア (B0E9h/B0EAh/B0EBh) を削除。
  ストローブ後 `nop` ×4 (マトリクス安定待ち) は実機向けに残置。
- 既知の小問題: MSG_STGn の空白が 00h (終端コードと共用) のため
  バナーは「STAGE」までしか表示されない (数字未表示)。

## 2026-11 描画不具合の解消 (スクロール方向 & 残像・黒列)

- **スクロール方向を逆転**: `do_scroll_shift` を「行を上へ LDIR + 最下段に新行」から
  「行を**下へ LDDR** (重なりシフトのため後方コピー) + **最上段**に新行」に変更。
  地形が上端から入って下へ流れる = 前進 (魔城伝説型) の見た目になる。
  敵 (y=0 から降下)・自弾 (上昇) との方向整合も回帰テスト済み
  (1066f のミラー行1-21 == 1060f の行0-20 を機械検証)。
- **ERASE2X2 の D レジスタ寿命バグ解消** (自機右下に黒セルを毎フレーム焼き付ける):
  BR 値を D に保持したまま `ld de,39` を再ロードするため D=00h に壊れ、
  消去時に自機右下セルへ常に 00h (黒) を書いていた。シフトで下流に黒列として
  蓄積 (修正前のスクリーンショットの階段状黒塊の正体)。
  → BR 値は書き込み時にミラーから直接読み直す方式に変更。
- **ERASE1X1 の PCG 属性アドレスバグ解消** (1x1 オブジェクトの軌跡残像):
  属性を `セル+2000h` (F000h領域, 実質捨て) に書いており、旧セルの PCG 属性が
  4Ah (バンク1) のまま残って地形がバンク1パターンで描画されていた
  (炎状の残像連鎖・黒い軌跡の正体)。→ `+0800h` (DC00h 基準) に修正。

- デバッグ支援ツール追加: `tools/ppm2png.py` (PPM→PNG 変換),
